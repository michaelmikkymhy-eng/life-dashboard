# 02 · 意识与创作

放你自己写、或 AI 帮你整理的内容。**这里允许本地写入**，与 `01-日常管理` 只能云端写不同。

| 目录 | 放什么 |
|---|---|
| `随笔/` | 成篇的想法、观察、读后整理 |
| `灵感/收件箱.md` | 随手记，先丢进来，每周日整理归位 |
| `精神成长/` | 目标、错题本、失败收集册 |
| `剧本/` | 剧本研究与创作 |

## 外部 AI 写入通道

任何能访问本地文件夹的 AI 工具（Claude Code、Cursor、Trae、Hermes 等）都可以把内容写进本目录，Obsidian 会立即显示。写入约定：

1. **允许写**：`02-意识与创作/`、`03-项目/`、`04-AI工具箱/`、`05-AI共研/`
2. **禁止写**：`01-日常管理/`、`99-系统/`。日记、Excel、规范和命令只由云端 `sync.py` 维护，本地改了会造成两边失配
3. **一篇随笔一个文件**：`随笔/YYYY-MM-DD-标题.md`，开头写 frontmatter（见 `99-系统/模板/随笔模板.md`）
4. **临时捕获**：追加到 `灵感/收件箱.md` 末尾，不要覆盖或重排已有内容
5. **编码与行尾**：UTF-8、LF；不要写 BOM
6. **不要删除或重命名**别处已有的文件
7. **推送失败先 `git pull --rebase`**，不要 force push
8. **不写密钥、token、密码**

## 命名示例

```text
随笔/2026-11-22-关于长期记录的一点想法.md
```

frontmatter：

```yaml
---
date: 2026-11-22
source: claude-code
tags: [记录, 方法论]
---
```

`source` 写工具名即可，方便以后知道这段内容是哪个 AI 产生的。

## 云端与本地的关系

本地 AI 写完文件，Obsidian 立刻能看到。要让云端和其他设备也拿到，需要 Obsidian Git 自动提交推送；云端在写入前会先 `git pull --rebase`，不会覆盖你本地的随笔。
