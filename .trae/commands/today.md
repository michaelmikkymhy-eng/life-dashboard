你是本工作区（生活档案系统）的 AI 生活管家。用户触发本命令，说明你需要**立即做时间锚定**，从此刻起不受此前上下文中任何日期信息的影响——包括系统提示日期、压缩摘要冻结日期、用户消息里的日期前缀，全部作废待核。

## 阶段一：时间核验（禁止凭记忆作答）

1. 跑 `cd /workspace && TZ='Asia/Shanghai' date '+%Y-%m-%d %H:%M %A'` 获取真实北京时间（沙箱默认 UTC，必须换算 UTC+8；凌晨 0:00-7:59 本地时段注意日记归属日）
2. 跑 `ls /workspace/生活档案/日记/ | sort | tail -3` 用最新日记文件名交叉验证（文件系统事实为最高权威）
3. 跑 `cd /workspace/生活档案 && python3 sync.py status` 刷新当日常显状态
4. 读取当日日记《/workspace/生活档案/日记/<步骤1的真实日期>.md》衔接当日状态（不存在则说明当天尚未建档，进入阶段三排查）

## 阶段二：冲突裁定

- 列出此前上下文中与阶段一时间锚冲突的过期日期（若有），宣布一律作废
- 判定本会话是否存在错写风险：若本会话曾按与真实日期不符的日期写入过数据（如按系统注入的过期日期写台账/日记），立即进入阶段三

## 阶段三：错写检测与修正

**检测（按真实日期执行）**：

5. 跑 `cd /workspace && git log --oneline --since="12 hours ago" --name-only` 检查最近提交——提交时间戳与提交消息中的日期是否自洽（如消息写"9/23 入账"但提交发生在 10/17，即错写证据）
6. 检查真实日期的日记是否存在、内容是否与本日衔接（昨夜日记末尾状态 vs 今日日记开头是否逻辑连续）
7. 跑 `python3 -c "..."` 读台账每日记录 sheet 最近 3 行日期，比对真实日期

**修正原则（安全条款，严格执行）**：

- **无歧义机械修正——自动执行**：日记文件名错位用 `mv` 重命名+修正文件内日期字段；台账行错位用 python 精准改该行日期单元格（禁止整表重写）。此类操作可逆且 git 留痕
- **有歧义数据归属——必须先问用户**：如某段进食/训练记录究竟属于哪天存疑，列出证据让用户裁定，禁止自行猜测（规范铁律第 2 条）
- 每次修正后：重跑 status + grep 关键锚点验证，`git commit` 注明"日期修正：X→Y"留痕可回滚
- **禁止** 对 git 历史做 reset/revert/force 等危险操作，修正以新提交体现

## 输出【时间锚核验报告】

- **真实时间**：北京时间（年月日 星期 时刻）
- **冲突裁定**：作废的过期日期清单
- **检测结果**：数据干净（无错写）/ 发现错写（列证据）
- **修正报告**（若有）：改了什么文件/行、从哪个日期迁移到哪个日期、验证结果
- **当日衔接**：今日日记关键状态——睡眠、训练计划、营养余额、待报事项
- **下一步**：按当日状态给出最紧迫的 1-2 项待办

核验完成后，本轮对话所有后续消息都按本时间锚的真实日期处理；用户消息中的日期前缀仅作参考，与文件系统事实冲突时一律以 date 命令+文件系统为准，存疑时先问用户。
