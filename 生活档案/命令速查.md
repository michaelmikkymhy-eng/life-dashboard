## 〇、日期锚定（2026-10-02 立此存照，最高优先级）

**会话开始 / 压缩续接后，回答任何"今天/现在/今晚练什么"类问题前，必须先用文件系统事实锚定实际日期：**

1. `ls 日记/ | sort | tail -3` —— 最新日记文件名即最新日期
2. `git log -1 --format="%ci"` —— 最近提交时间戳
3. **与系统提示日期/压缩摘要日期矛盾时，一律以文件系统为准**；仍拿不准，直接问用户，不猜

> 教训案例（2026-10-02）：压缩会话携带的系统日期停在 9/23，实际已是 10/2 凌晨（中间 8 天由其他会话维护）——未核实就报训练日，把用户顺延好的背+二头重启日报成肩主训，用户在健身房收到完全错误的计划。此后凡日期存疑，先 ls + git log，再开口。
> 教训案例（2026-10-04，第 6 次复发）：条文立了也拦不住"失忆会话"——压缩续传的新会话**不会主动读本文件**，摘要仍冻结在 9/23，10/4 的训练/采购/库存又被错写进 9/23。故本日已把闸门下沉到 sync.py 脚本层（见下条），物理拦截。

**⚡ 日期哨兵（2026-10-04 起，已内置 sync.py，自动生效无需记忆）**

- 写入命令（meal/expense/income/sleep/train/timeline/mantra/weight/dim/deed/effort）：`--date` 距真实今天 >3 天且未加 `--backfill` → **拒绝执行**（退出码 3 + 提示核实日期）
- 被拦截说明你（AI）的上下文日期多半过期了：先跑 `date` + `ls 日记/ | sort | tail -3` 校准，再把数据写到正确日期
- 真补录历史（用户明确要求）：命令加 `--backfill`，输出会带"⚠️ 补录模式"留痕
- 只读命令（check/weekly/monthly/today/status）不受影响

## 已知坑

1. **文件回滚——根因已查明（2026-09-03 排查）**：/workspace 是 virtiofs 宿主共享盘，回滚发生在**宿主侧同步层**（沙箱内 ps 验证无任何同步工具）；签名=markdown 表格补空格+空单元格 `<br />`；只回滚宿主缓存过的旧文件，新建文件不受影响；沙箱重启后为高发窗口。用户 git 史 8/8"云端同步覆盖丢数据"为同源慢性病。
   - **看门狗（第一道防线，2026-09-03 上线）**：`/workspace/.watchdog/watchdog.py` 常驻，3s 轮询全部 .md/.xlsx，归一化哈希+版本历史，检测到回滚自动恢复+留证（`/workspace/.watchdog/events.log`）。**每轮对话开始先查活**：`for pid in $(pgrep python3); do tr '\0' ' ' < /proc/$pid/cmdline | grep -q watchdog && echo alive; done`，无 alive 则 `nohup python3 /workspace/.watchdog/watchdog.py >/dev/null 2>&1 &`（state/版本库存 /workspace/.watchdog，跨沙箱重启持久；⚠️ /data/user/work 是临时盘，沙箱重启即清空——2026-09-03 实测，任何需留存的工具/数据一律放 /workspace）
   - **git 基线（终极兜底）**：`cd /workspace && git add 生活档案 && git commit`——重要写入回合结束后提交；恢复 `git checkout -- <file>`
   - **提交也可能被污染（2026-09-04 实锤）**：回滚可发生在锚点终检之后、git add 之前，commit 捕获回滚态（ff143e4 即此例）。铁律：重要文件 commit 后必跑 `git show HEAD:<file> | md5sum` 对比磁盘哈希，不一致=已污染，重写重提
   - 助手批量写文件期间 `touch /workspace/.watchdog/pause.lock`、写完 `rm`（防半写状态被记为版本）；**沙箱意外回收会留死锁**——复活看门狗后若日志无动作，查 `ls .watchdog/pause.lock`，删前先仿真首轮轮询（对每个受监控文件算当前哈希：命中 history 但 ≠latest 的先处理，DANGER=0 才删；2026-09-06 实测遗留锁致空转）
