## 〇、记录铁律（最高优先级，2026-08-28 立此存照）

**1. 只记录用户确认过的事实。计划 ≠ 完成，惯例 ≠ 发生。**

- 训练计划里的补给/有氧，用户没说"喝了/做完了"就绝不写入数据

- "老样子"不等于"这次也是"，每次以用户本次实际说的为准

**2. 任何不确定，先问后写，绝不猜。**

- 涉及库存（开了新盒？喝了多少？买没买？）、日期归属、金额、来源的疑问，一律先问用户

- 问完拿到答案再动数据，宁可多问一句，不可错记一条

- 错误假设写入台账会污染库存和营养数据，回退成本远高于先问一句

**3. 用户汇报 ≠ 已发生（2026-08-29 立此存照）。**

- 用户报生熟重量换算、报"打算吃多少"、报参考数据，都只是**信息**，不是进食确认

- 只有用户明确说"吃了/吃完了/记账"才入账；"算一下/吃多少合适"类请求，先给数字，等用户吃完回报再动数据

- 用户主动报数 ≠ 授权入账，宁可等一句"吃完了"，不可抢先记一笔

> 教训案例（2026-08-28）：擅自假设"练后喝了补给+开了新牛奶盒"，导致牛奶库存虚记 712.5ml、热量虚增 264.8 kcal，后经用户纠正全部回退。此后凡不明确处，一律先问。
> 教训案例（2026-08-29）：用户汇报"3盒虾仁煮出来407g"是生熟换算参考，我擅自当作已吃入账三笔（青虾仁540g+牛肉丸160g+白虾仁50g），用户纠正"还没吃，只是汇报"，已全部回退。汇报类信息先当咨询处理。

**4. 日期锚定：不信提示信文件（2026-10-02 立此存照）。**

- 会话开始或压缩续接后，禁止直接沿用系统提示/摘要里的日期回答"今天/现在"类问题

- 动手前必须 `ls 日记/ | sort | tail -3` + `git log -1` 核实最新日期；与提示矛盾时以文件系统为准，仍拿不准就问用户，不猜

- 涉及训练日判断时，在此基础上再读最新日记 + 本文件「周训练计划」表（铁律 12），三对齐后才开口

> 教训案例（2026-10-02）：压缩会话携带的系统日期停在 9/23，实际已是 10/2 凌晨（中间 8 天由其他会话维护）——未核实就回答训练问题，把用户顺延好的背+二头重启日报成肩主训，用户在健身房收到完全错误的计划。此后凡日期存疑，先 ls + git log，再开口。
> 教训案例（2026-10-04，同一天第 6 次复发）：本条 10/2 已立，但**新压缩会话开工不读规范、摘要又冻结在 9/23**，条文对"失忆后的我"无效——10/4 的训练+采购又被错写进 9/23（训练记录覆盖原值/库存回滚 8 项/财务错挂）。证明：**靠"读规范"防不住，必须靠脚本闸门。**

**⚡ 升级（2026-10-04）：日期哨兵已内置 sync.py（物理闸门，不再依赖记忆）**

- 所有写入命令（meal/expense/income/sleep/train/timeline/mantra/weight/dim/deed/effort）执行时自动校验：`--date` 距真实今天 >3 天且未加 `--backfill` → **直接拒绝执行**（退出码 3）
- 历史确需补录（如出差回来补一周）：显式加 `--backfill` 放行并留痕"补录模式"
- 效果：即使会话上下文冻结在旧日期、AI 失忆，错写也会在数据入口被物理拦下，无法污染台账
- 10/04 已三场景实测：旧日期拦截 ✅ / 当日放行 ✅ / --backfill 放行 ✅

## 二、沟通方式

   - 但每次回复底部**必须显示常显信息**（营养余额+提醒）

2. **常显信息（每次回复底部必带）**

3. **时间默认锚定当下（2026-10-02 约定）**

## 三、记录规则

> **AI 助手必读**：新对话动手前先读《命令速查.md》（命令用法+已验证事实+已知坑），不要翻 sync.py 源码——省 token 省轮次（2026-09-02 约定）。

### 三文件同步原则

**每次记录必须同时更新三个文件，关键数据保持一致：**

1. **日记**（`日记/YYYY-MM-DD.md`）— 完整详细记录（饮食明细、训练内容、消费、库存变化、备注）
2. **台账**（`生活数据总台账.xlsx`）— 结构化数据

   - 每日记录 sheet：每日汇总

   - 财务明细 sheet：每笔消费

   - 盒马营养成分 sheet：食材营养数据

   - 准提咒进度 sheet：功课进度

   - **食物库存明细 sheet：食材库存核查**

   - **体成分记录 sheet：每次称重全指标（参考资料，2026-08-24 建）**
3. **使用规范**（`使用习惯与规范.md`）— 规则、习惯、目标有变时立即更新

> 严禁只更新一个文件不更新另一个。关键数据（热量、蛋白、消费金额、库存数量等）必须一致。

### 营养数据取数口径（2026-09-01 定规）

- **无包装标签、靠网络数据库估算的食品：各家口径不一致时，取"中间偏高"值入档**——宁可热量多算，不可少算后吃多不自知（案例：肯德基香辣鸡腿堡各家 232-296kcal/100g，取 274 入档；宏量素按新热量等比缩放）

- 入档时在备注注明取值依据和各家区间，后续拿到实测标签再更正

**防错设计要点（对应"记错记乱决不允许"）**：

1. 写前自动备份到 `备份/`（保留 30 份）；临时文件 → 重开校验 → 原子替换，失败不碰正式文件
2. 落盘顺序：台账原子写成功才写日记，杜绝"日记有、台账无"的半写状态
3. 名称匹配宁可问不可猜：多个候选直接报错列出；食物匹配不到先 `food` 录入
4. **排序规则**：每日记录/财务明细 = 物理严格倒序（最新永远在第 2 行，同日多笔最新在最上）；准提咒进度 = 严格正序（累计列从上往下才成立）。表头永远第 1 行且有内部断言
5. 表格筛选按钮（AutoFilter）只是查看辅助：**顺序永远以物理行序为准**。即使在 Excel 里手动排序弄乱了，下次脚本写入会整体重排自愈，`check --all` 也能查出
6. 所有写命令支持 `--dry-run` 预演
7. **读图防错（2026-08-24 新增）**：截图/照片里的数字（体重、金额、营养表）必须现场重新读图取数，禁止凭印象或凭上次记录报数；关键数字先报给用户核对，确认后才写入。称重报告重点核对"体重"行，不得与肌肉率/去脂体重/骨骼肌量混淆（8/24 曾把 69.05kg 看错）。称重截图还要核对拍摄/上传时间与称重日是否一致，不一致先问
8. **称重日习惯（2026-08-24 定）**：周一空腹称重后，用户发 App 的「指标对比」截图（两个日期并排，最不容易看错行）；全指标用 `weight --body` 入「体成分记录」表，日记同日存全指标表+周对比摘要。周对比以 App 指标对比页为准。趋势关注：内脏脂肪目标 <10 级、蛋白质率 ≥16%、体脂率降+骨骼肌量稳=理想减脂

16. **薄弱点追踪（2026-08-31 定，用户要求）**：训练中暴露的左右不平衡/薄弱环节，必须当场排进周训练计划对应部位的训练日（主训日+轻量日都排，动作带「补强」标注+具体组数重量），让用户训练日看计划就知道哪天补强。首例：8/31 单臂哑铃划船左侧发力感明显更弱 → 已排入周一主训日⑤、周五轻量日⑤；补强期右侧同动作不加重量，直到用户汇报左右发力感一致，才从计划撤销
17. **当前日期判断基准（2026-09-24 立，用户批评立规）**：环境时间戳可能滞后（9/24 会话环境曾仍显示 9/23），判断"今天是几号"一律以**用户最新汇报内容 + 台账最新记录**为准（例：台账已记录 9/24 上午数据 → 当前日期即 9/24）。不得向用户问"今天是几号"级常识问题，也不得把用户报的新数据挂到滞后日期上；账单归属仅在报账含糊且台账无线索时确认购买场景，不得问日期本身
18. **财务口径铁律（2026-11-04 立，用户两次纠正）**：**禁止把支出与退款相加后报成"赚/节省/净赚"**。退款只是"已花出去的钱退回账户"，与"根本没花这笔钱"不是一回事；净额（支出−退款）只表示**当期账户现金净流出**，不含任何"省了""赚了"的含义，也不能拿来比较消费水平。汇报大额或衣类消费必须分三行给：**毛采购金额**（下单总额）、**退款金额**（负数单列）、**不可退成本**（运费等），最后才给净现金流出并注明"仅代表账户变动"。有意义的口径是：**保留商品成本、退货率（笔数/金额双算）、不可回收成本**。11/04 曾把「采购 1818.75、退款 1238.76」错报为"净赚 45.28"（还把退款重复减了一次），立此存照
19. **时间与时区（2026-11-04 立）**：本机 `date` 输出的就是**用户本地时间（CST, UTC+8）**，不要再手动加 8 小时。11/04 曾把 07:50 CST 换算成"15:50"，被用户当面纠正。日记日期直接用 `date` 的日期部分即可，无需 UTC 折算（AGENTS.md 里"沙箱为 UTC"的说法已过期，以此条为准）
20. **库存扣减不得重复（2026-11-04 立，用户纠正"数学这么差"）**：补记采购时必须走「先 `stock --set 采购总量` → 再 `meal` 记账让它自动扣减」的顺序；**禁止先把库存手算成"剩余"再补记餐**，那会扣两次（11/04 沙茶酱 200g 吃 20g 被扣成 160g）。已在当天餐全部记完的情况下，`stock --set` 的值 = 采购总量 − 已食用量，写完立刻回读核对（200−20 必须等于 180）

### 时间轴（日记展示层，2026-08-31 起，用户提议上线）

> 目的：把点状记录连成线——一眼回看当天各时段在做什么，空白时段自动暴露，回忆有锚点。

- **位置**：日记「作息」节后、「准提咒」节前，节名「时间轴」

- **格式**：`| 时段 | 时长 | 类别 | 内容 | 标记 |`，按开始时间排序

- **数据来源**：用户随口报的带时间事项（"04:22 开始 X"）+ 睡眠时段 + 三餐（有报时间时）+ 准提咒

- **重叠允许（用户明确要求）**：不同事项时间可重叠（如系统构建 04:22-06:20 与做饭 04:24-05:20 并行），重叠项「标记」列标「重叠」，不强行拆成单线

- **时间未知**：只有时长没时段的事项（准提咒、未报时间的加餐等）归入节末「### 时间未知」小节，**不硬猜时段**

- **默认时长（用户 8/31 定）**：准提咒 108 遍=0.5h、54 遍=0.25h——**仅时间轴展示用，不折进努力度计分**（准提咒是独立加分项，混入深度成长会虚增分数）

- **清醒期**：起床后到做事间的发呆/清醒期，用户提及时记「恢复·清醒期」

- **推定标注**：结束时间未报的，按合理边界推定并在内容注明「推定」，用户可随时更正

- **做饭口径（2026-08-31 用户定）**：做饭结束时间 = 开饭时间，直接落账不问

- **准提咒时段（2026-08-31 用户定）**：一般是做完才汇报——汇报时刻 = 结束时间，开始时间 = 汇报前半小时（108 遍 0.5h / 54 遍 0.25h 正好吻合）

- **即时汇报暂定法（2026-08-31 用户定）**：健身/吃饭等即时汇报时，以汇报时间暂定开始或结束时间，另一端不明确时先问用户确认再写，减少猜错

- **口径**：时间轴是展示层，结构化时长以成长流水/训练/睡眠记录为准；只管 8/31 起，历史日期不回溯（数据不全、时段无法确定）

## 四、努力度评估体系（恐惧驱动·客观标准，2026-08-20 建立）

> 目的：把"我今天是否虚度"从感觉变成数字。数字不安慰、不审判，只指路——分数低看缺口，不看情绪。

### 等级

S ≥90 精英日 · A ≥80 **两成日** · B ≥70 中坚日 · C ≥60 普通日 · D <60 虚度警报

### 防误伤铁律

1. **未记录 ≠ 0分**：缺数据的维度显示"缺"，不打负分、不触发负面标记（防止"忘了记"被当成"没做"而焦虑）

   - **例外（2026-08-31 用户定规）**：深度成长未汇报时**默认按"无"（0h）计分并正常评级**——用户有的话会补录，补录后重跑 effort 即自动更正。即深度成长不再走"未记录挂缺"逻辑，未汇报=事实上的无
2. **完整度 <80% 不给等级**：只记了睡觉和吃饭的一天不评定，等补录（深度成长除外，见第1条例外——它默认已计为无，不拖完整度）
3. **负面标记三条件全中才触发**：虚度嫌疑（深度成长<1h且非休息日）、逃避模式（睡眠>10h且深度<1h）、暴食补偿（热量超50%且深度<1h）——深度成长未汇报按0h计，同样参与触发；防误伤机制是"用户随时可补录更正"而非挂起不评
4. **日期不确定就问，绝不猜**：用户作息特殊（凌晨活动、跨天睡眠等），任何"该记昨天还是今天"拿不准的情况，直接问用户，不自行判断。用户说记哪天就记哪天。
5. **数据不确定也绝不猜**：库存增减、补给是否发生、消费归属——一律先问后写（见"〇、记录铁律"）。

### 输入/输出与一万小时仪表盘

### 关键饮食原则

1. **训练前一定要吃碳水** — 只喝蛋白粉训练质量上不去，加个香蕉或欧包

3. **脂肪不用刻意控** — 吃的都是瘦牛肉和虾，脂肪自然够。注意素拌菜脂肪不低（21.5g/100g）
4. **每周 1 顿欺骗餐没问题** — 新手期代谢高，不影响，反而有助恢复
5. **优先食材**：

   - 蛋白：帕斯雀牛肉片、牛腱切片、凉拌牛肉、北极甜虾、蛋白粉、牛奶、溏心卤蛋

   - 脂肪：牛奶、牛肉自带、素拌菜

### 重组计划（减脂优先+保肌 · 糙米时代）

> **启动口令**：用户说「**重组计划启动**」时，立即切换到此计划，替换当前饮食目标和模板。

- 餐次从4-5餐精简到2餐，减少进食窗口

### 压缩计划（2026-08-24 定 · 12 月初见 12% 体脂）

> **定位**：用户 8/24 提出加速——"四个月太久"。压缩计划 = 重组计划的执行强化版，热量与宏量目标不变（训练日1900/休息日1650，蛋白120-140g，脂肪45-70g），提速靠「每周 7 天全执行 + 睡眠连续 + 有氧加量」，不是砍热量。

#### 目标时间线

- 减脂节奏：**每周 -0.6\~-0.7kg**（快于重组计划的 0.4-0.6，但不超过 0.75 保肌线）

- **月度考核校准（2026-09-01 定，8 月复盘结论）**：月报检查点"月减重 2.7-3.3kg"系节奏上限换算值，8 月实绩 1.1kg/月且去脂体重持平=高质量慢减；**9 月起月度考核线改为：月减重 1.8-2.2kg（0.4-0.5kg/周）+ 体脂率月降 1.5-2pp（主指标）+ 骨骼肌率 ≥45% 不降**。提速靠结构（蛋白四锚点 135g/天、高脂餐>40g 锁零脂、23:30 入睡线、休息日 1650 真执行）而非砍热量，红线全部不动。详见 8 月月报第九章。

- 体重验证：每周一空腹称重；连续 2 周低于 0.5kg/周 → 优先加有氧，不砍热量

#### 提速三杠杆（优先级排序）

1. **睡眠连续 ≥7h**：压缩计划的第一优先级，凌乱的睡眠直接毁掉一周缺口（8/18 通宵→当天3466kcal、当周掉0.9kg肌肉的教训）。睡眠<7h的日子不加练，优先补觉
2. **有氧加量（2026-09-01 升档）**：训练日爬坡 45-50 → **55min**（周一\~周六统一）；周日休息日 **30-40min 快走**（不影响恢复）。爬坡按 6.5kcal/min 计，55min≈357kcal/节，26 训练日/月 ≈ +9300kcal/月
3. **热量降档规则（2026-09-01 定，用户授权"可减但别伤肌"）**：**默认不降**——1900/1650 本身=实测 TDEE 2231 的 -15% 缺口，已处保肌安全边缘（蛋白 1.8g/kg 体重勉强护航）。**仅当** 7 日滚动均值连续 2 周 <0.30kg/周且执行度已拉满时，训练日 1900→1800（缺口 -21%），**不破 1800**；降档后若骨骼肌率跌破 45%，立即回 1900。肌肉量是杠杆的支点，砍太狠杠杆就断了
4. **训练密度**：主训动作 5 组、组间休息 60-90s；轻量日（周五/周六）用超级组（拮抗肌配对：划船+卧推、弯举+下压），同样时间多榨 15-20% 容量

#### 红线（提速时严禁触碰）

- ❌ 热量砍到 1900/1650 以下（复制"掉肌肉"剧本）

- ❌ 肩痛动作加强度（夹胸类暂停 2 周，无痛后再恢复——停训 6 周才是最慢路线）

- ❌ 睡眠 <7h 的日子加练

- ❌ 每周减重 >0.75kg（肌肉流失风险线）

#### 热量补偿规则（2026-08-26 定）

某天吃超了，**允许在本周内或下周内通过减少热量补回来**，属于计划内的补救行为，不算"破功"。

- 补偿方式：少吃一顿/减少碳水/加有氧均可，目标是让周平均热量仍在目标区间

- 单天超量 ≤ 300kcal：当天或次日就能找平

- 单天超量 > 300kcal：分 2-3 天慢慢找平，不要一天砍到 1200 以下（会掉肌肉）

- 周报时看"周平均热量"是否达标，单天超标但周平均在目标内即算合格

- ⚠️ 连续 3 天超标 → 不是补偿问题，是节奏乱了，需要拉回正轨

#### 每周检查点（周日周报时对照）

- 体重降幅是否在 0.6-0.7kg 区间

- 蛋白 7 天中 ≥6 天达到 120g+

- 骨骼肌量（周一体成分）不下降（上周 -0.9kg 的教训）

- 任一条连续 2 周不达标 → 降回重组计划节奏，不硬冲

### 新手红利期判断

**什么是新手红利期（Newbie Gains）**：刚开始训练的前 6-12 个月，身体对训练刺激反应极强，肌肉和力量增长最快的阶段。

**新手红利期的特征（你现在就在里面）：**

- 力量每周都在涨（你 12 天卧推从 12.5→15kg，就是典型）

- 每次训练都能比上次多做几个

- 肌肉肉眼可见地变大变结实

- 即使体脂还高，也能一边增肌一边减脂

**怎么判断结束：**

| 信号           | 说明                              |
| ------------ | ------------------------------- |
| 力量连续 2-3 周没涨 | 最核心信号，同一个动作同样次数，重量加不上去了         |
| 需要刻意计划才能进步   | 之前随便练就涨，之后需要周期化、减载、变换动作         |
| 肌肉增长速度明显变慢   | 前 3 个月每月长 1-2kg 肌肉，之后降到 0.5kg/月 |
| 体重不变但力量涨不动   | 神经适应基本完成，接下来才是真正的"增肌"           |

**大致时间线：**

- 第 1-3 个月：神经适应期（力量暴涨，主要是神经效率提升，肌肉量涨得相对少）

- 第 3-9 个月：真正的新手增肌期（肌肉快速增长）

- 第 9-12 个月：红利期末尾（增速明显放缓）

- 1 年以后：进入中级阶段，进步需要更精细的计划

**抓住红利期的关键：**

1. 渐进超负荷 — 每次训练力争多 1 个或加 2.5kg
2. 蛋白质吃够 — 1.6-2g/kg 体重（你 70kg = 112-140g）
3. 睡眠 7h+ — 肌肉在睡眠中生长
4. 不瞎换动作 — 一个动作练透了再换
5. 别过度训练 — 休息也是训练的一部分

## 八、周报机制

### 周报时间

- 定时任务**每周二 10:00** 生成**上一周**周报（周一\~周日完整周）；也可手动 `python3 sync.py weekly --date 2026-08-28`（该日期所在周，只读，输出到终端后落盘）

- 保存路径：`生活档案/周报/第X周周报_周一日期_周日日期.md`（如 `第35周周报_2026-08-24_2026-08-30.md`）

### 周报内容（固定 8 章）

1. **体重与体成分** — 周初 vs 周末后全指标对比 + 每日晨重走势 + 周均体重
2. **营养** — 热量/蛋白/脂肪/碳水周平均 + 达标天数
3. **训练** — 训练天数、有氧累计、训练分布
4. **睡眠** — 日均睡眠、≥7h 天数
5. **深度成长** — 各领域输入/输出时长
6. **消费** — 总支出、分类占比
7. **压缩计划检查点对照** — 周减重/蛋白/睡眠/骨骼肌量
8. **本周总结** — 亮点/问题/下周改进建议

### 体重信息规则（2026-09-01 定）

- 周报体重章**必须有体重信息，不允许空章节**

- 优先体成分配对：周初 = 周内最早一次（周一有记录即周一）；周末后 = 周日之后\~下周四内最早一次（收尾称重可能漂移到下周二/三，如 8/30 周的收尾称重实际落在 9/1）

- **周内无配对体成分称重时**：以每日晨重中**临近周一**和**临近周日**（各 ±3 天窗口内就近取数，可用周边界外邻近数据）的记录为主算周变化，表格标注"临近周一（日期）/临近周日（日期）"

- 补充展示：每日晨重走势 + 周均体重（2026-09-01 每日称重制配套）

- 检查点"周减重"沿用同一对锚点，保证章节数据一致

- 训练、营养、睡眠、每日晨重：从「每日记录」sheet 提取

- 体重与体成分全指标：从「体成分记录」sheet 提取

## 九、习惯追踪：失败收集册（2026-09-20 建立）

**核心逻辑**：失败的越多，成功的越快——失败是垫脚石不是污点，用"记录+复盘"把每次失败的代价兑现成经验。心态目标：遇到问题 回避 → 面对问题 兴奋。

**主文件**：`生活档案/失败收集册.md`（游戏规则、心态量表、勋章里程碑、统计面板、全部收集记录）

### 使用方式（贴合习惯：你只管说，我来记）

- 遇到失败/挫折/尴尬/被拒绝/难题卡住时，说 **"我收集了一个失败：[场景]"** → 我按固定模板记一条（编号+日期+场景+本能反应+实际行动+学到+心态等级）
- **主动狩猎**：每周 ≥1 次自设障碍（做一件"有点怕/可能出丑"的事），完成后同上记录并标注"主动狩猎"
- 心态自评三级：😨L1回避 / 😐L2面对 / 🔥L3兴奋——用户未自评时由助手按描述推断并注明，可随时更正

### 统计与激励

- 每枚更新收集册统计面板（累计/主动狩猎数/心态分布/勋章进度）
- 勋章里程碑：🥉10枚 / 🥈30枚 / 🥇60枚 / 💎100枚（宗师·障碍美食家）
- 常显信息可附：`🪨 失败收集：X 枚（下一勋章还差 Y 枚）`
- 周报"深度成长"章后附本周收集数与心态分布（助手手动汇总）

### 边界（不入账规则）

- 收集失败 ≠ 深度成长时长：记录复盘动作本身（几分钟）**不记 deed**
- 若某次失败引发 ≥30min 专注深度复盘且有产出，可按领域清单记 deed（如系统建设）；是否新增"心态管理"领域，届时先问用户（新领域规则见"领域清单"）
